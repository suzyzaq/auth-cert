# 独立规则中心设计

## 目标

为授权资质巡检工作台增加独立 `/rules` 页面，让巡检员、复核员和管理员能查看
当前生效规则、风险等级、适用字段和最近运行结果。同时提供授权资质数据库的公开
入口，方便对照原始查询结果。

## 页面结构

顶部导航调整为：

1. 任务中心
2. 管理总览
3. 规则中心
4. 授权资质数据库（外部链接）

规则中心延续现有工业编辑风格，包含：

- 页面标题和规则运行状态；
- 规则总数、启用数、严重规则数、待调整数四项指标；
- 规则分类筛选、风险筛选和关键词搜索；
- 规则卡片列表；
- 单条规则详情区，展示规则说明、校验字段、触发条件、风险等级和最近命中数。

## 规则分组

首版固定展示六组规则：

1. 接口可用性：索引和分片返回 200、JSON 可解析、边界分片返回 404；
2. 数据新鲜度：OSS 当天或前一工作日更新，CDN 最多滞后两天；
3. 索引一致性：`shardCount`、实际分片数、`brandCount` 和品牌键数一致；
4. 字段完整性：授权记录检查 `code/name/type/level/grant/authed/enable/disable/flag/flagText/files`；
5. 业务逻辑：日期先后、授权链、品牌与品类匹配、低置信度结果进入人工复核；
6. 证据贯通：品牌能够定位分片，授权或资质记录非空，附件证据可以访问。

## 交互与权限

- 所有角色均可查看规则和筛选结果；
- 首版启停控件仅展示当前状态，不在浏览器内直接发布规则；
- 管理员修改规则必须经过后端版本校验、变更摘要和二次确认；
- 规则变化不会直接触发数据库回写，只影响后续巡检批次；
- 严重规则使用橙红标识，普通异常使用蓝色，正常启用使用绿色。

## 外部链接

授权资质数据库链接固定为：

`https://suzyzaq.github.io/auth-cert-db/`

链接在新标签页打开，并使用 `noopener noreferrer`。不拼接品牌、任务编号、用户信息
或任何内部查询参数，避免向外部页面传递巡检数据。

## 数据与错误状态

首版使用明确的规则模型：

- `id`
- `name`
- `category`
- `description`
- `severity`
- `enabled`
- `fields`
- `condition`
- `hitCount`
- `lastRunAt`

加载失败时显示独立错误区；无匹配结果时提示调整筛选条件；规则数据未连接后端时标注
为演示数据，不伪装成实时发布状态。

## 验收标准

- `/rules` 可从顶部导航进入，刷新后仍能正常显示；
- 外部数据库链接地址正确并在新标签页打开；
- 搜索、分类和风险筛选能组合使用；
- 六类规则均有代表性规则；
- 页面在桌面和窄屏下无横向溢出；
- 自动测试覆盖导航、外链属性、筛选和规则详情；
- 全部测试、类型检查、代码规范检查和生产构建通过。
