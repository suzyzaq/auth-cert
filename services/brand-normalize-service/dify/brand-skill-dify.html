附件品牌 vs 数据库品牌 标准化比对 · 确定性规则引擎 · 本地库 + SCS 回退(仅启用) · 无 LLM

① 服务与鉴权 ▾

服务地址
http://YOUR_HOST:8000 （部署后替换，建议内网/同VPC）
业务端点
POST /api/brand/normalize · POST /api/brand/reload · GET /health
鉴权
Bearer Token（环境变量 BRAND_API_TOKEN，Dify 侧放「环境变量」勿硬编码）
Header 写法
Authorization: Bearer <BRAND_API_TOKEN>
/health
免鉴权，但仅返回 status/brand_count/alias_count/data_version/scs_enabled，不泄露路径
Dify 自定义工具：导入 brand-normalize-tool.openapi.json，鉴权选 API Key → Header 名 Authorization → 值 Bearer <token>。

④ 工作流条件分支（IF/ELSE） ▾

HTTP 请求节点→ 代码节点(解析 body)→ IF/ELSE 分支
判定条件分支动作标签
same_brand==true 且 needs_manual_review==false品牌一致，审核链路自动通过自动通过
match_type==conflict附件与数据库命中不同标准品牌，判不一致冲突
needs_manual_review==true转人工复核，写入钉钉AI表格队列(带 match_basis+scs_candidates)人工复核
scs_hit==true（任一侧有 scs_candidates）标记「SCS候选」，人工确认后沉淀本地主库SCS回退
 
def main(body: str) -> dict:
    d = json.loads(body)
    return {
        "same_brand": d.get("same_brand", False),
        "needs_manual_review": d.get("needs_manual_review", True),
        "matched_standard_brand_id": d.get("matched_standard_brand_id", ""),
        "match_type": d.get("match_type", "unmatched"),
        "confidence": d.get("confidence", 0),
        "match_basis": d.get("match_basis", ""),
        "scs_hit": any(det.get("scs_candidates")
            for det in d.get("attachment_details", []) + d.get("source_details", [])),
    }

⑤ 业务红线（绝不可违反） ▾

附件品牌独立处理
附件与数据库品牌各自标准化，禁止用一方改写另一方
禁止跨品牌套用
不得把附件「佳能」归到数据库「惠普」
型号/品类≠品牌
型号、规格、单位、颜色不进入品牌判定
SCS 仅候选
SCS 命中只作候选，绝不自动确认 same_brand
仅启用品牌
SCS 查询强制 status=1，停用品牌不可用
下一步：人工复核确认 SCS 候选后，沉淀进本地 matcher.db（品牌主数据回流），SCS 依赖逐步收敛；复核结果经钉钉AI表格 → 批量导入 → POST /api/brand/reload 热生效。
