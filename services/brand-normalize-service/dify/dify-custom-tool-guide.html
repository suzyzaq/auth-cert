二、Dify Studio 导入 6 步

  1. 打开规范文件：本地打开 dify/brand-normalize-tool.openapi.json，确认 servers[0].url 已是你的真实地址（如 http://10.0.0.5:8000）。
  2. 进入工具页：Dify Studio 左侧 → 工具（Tools）→ 右上 自定义（Custom）。
  3. 导入 OpenAPI：选 导入 OpenAPI 规范 → 上传该 JSON 或粘贴内容 → 下一步。
  4. 核对端点：应自动列出 5 个端点 —— normalizeBrand / reloadBrandLibrary / normalizeCategory / reloadCategoryLibrary / brandServiceHealth。确认无报错。
  5. 配置鉴权：在工具鉴权设置选 API Key → Header 名填 Authorization → 值填 Bearer <你的 BRAND_API_TOKEN>。（Dify 读取规范里的 securitySchemes.bearerAuth 自动提示此步）
  6. 保存：保存工具。此后在任意聊天流 / 工作流添加该工具节点即可，无需重复配置。
若第 4 步 Dify 报「无法解析规范」：几乎都是 openapi 版本或 securitySchemes 拼写 —— 本规范已锁定 3.0.3 且拼写正确，正常不会出现。

三、调用时的变量映射

工具节点的输入变量，来自上游（开始节点 / 前序节点）的输出变量。两个能力域各自独立。

工具必填变量映射到上游
品牌 normalizeBrandattachment_values / source_values附件识别品牌 / 数据库登记品牌（支持数组、单串、逗号·顿号分隔）
品类 normalizeCategoryproduct_name / client_category商品名称 / 甲方类目
品牌节点 Body 示例（点击展开） 
{
  "task_type": "brand_standardization",
  "attachment_values": [ "{{#start.attachment_brand#}}" ],
  "source_values": [ "{{#start.db_brand#}}" ]
}
品类节点 Body 示例（点击展开） 
{
  "task_type": "category_standardization",
  "product_name": [ "{{#start.product_name#}}" ],
  "client_category": [ "{{#start.client_category#}}" ]
}
兜底规则（如 茶杯→陶瓷杯）命中在 client_category 上，记得把甲方类目传进 client_category。

五、（可选）API 导入 curl 模板

若你想程序化导入（不走 UI），Dify 企业版开放了应用/工具管理 API。模板如下，填 2 处即可运行（需你的 Dify API Key + Base URL）。

复制 curl 
# 说明：Dify 自定义工具的 OpenAPI 导入通常通过「应用 → 工具」UI 完成；
# 若用 API，一般是先建应用再绑定工具。以下为通用鉴权调用骨架，
# 具体端点以你的 Dify 版本文档为准（替换 <DIFY_BASE_URL> 与 <DIFY_API_KEY>）。

curl -X POST "https://<DIFY_BASE_URL>/v1/tools/import" \
  -H "Authorization: Bearer <DIFY_API_KEY>" \
  -H "Content-Type: application/json" \
  -d @dify/brand-normalize-tool.openapi.json
# 注意：@ 文件体需 UTF-8；如报编码，用 Python 读文件后 requests.post(json=...)
★ 我无法替你跑这条（无 Dify 连接器 / 无你的 Key）。你提供 <DIFY_BASE_URL> + <DIFY_API_KEY> 后，我可把它改写成确定可用的脚本并帮你验证返回。
