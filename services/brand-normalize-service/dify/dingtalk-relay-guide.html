让 云端 Dify（dify.ai） 无需公网/隧道即可调用本机 brand-normalize-service（localhost:8000）。 钉钉 AI 表格作为「云端可达的共享中转台」，把任务提交与结果回收解耦。本方案已端到端跑通验证。

核心结论： 云端 Dify 只负责往钉钉中转表写 pending 行； 本机常驻的 dingtalk_relay.py 轮询该表 → 调本机服务 → 把结果写回 result 列并置 done。 Dify 轮询读取结果即可。全程本机服务不出网，最稳。

③ 宿主机中继代理（已验证）

依赖与配置

  • 本机已运行服务：uvicorn app.main:app --host 0.0.0.0 --port 8000
  • mcporter（脚本自动定位；Windows 用 mcporter.cmd 包装，已处理）
  • .env 需含两项：BRAND_API_TOKEN=… 与 DINGTALK_MCP_URL="https://mcp-gw.dingtalk.com/server/…?key=…"

复制

行为要点

  • 只处理 status==pending 的行；处理前先置 processing 防重入/重复处理。
  • 按 task_type 分派到 /api/brand/normalize 或 /api/category/normalize（Bearer 鉴权复用 BRAND_API_TOKEN）。
  • 成功：写 result（完整响应 JSON）+ 置 done。
  • 本机服务瞬态不可达（连接失败）：保留 pending 下一轮重试，仅记日志，不写 error（避免丢任务）。
  • 真错误（4xx/业务失败）：置 error + 写 error_msg。
  • 日志落盘 .relay_log/ 便于追溯。

④ 云端 Dify 接入（无需公网）

推荐做法：Dify HTTP 请求节点直接 POST 钉钉 MCP 的 Streamable HTTP 地址（即 DINGTALK_MCP_URL 那个公网 URL）。 经实测，该端点无需 session 握手，直接发 JSON-RPC tools/call 即可读写。无需另建钉钉应用。
4.1 提交任务（写 pending 行） 
POST {{DINGTALK_MCP_URL}}
Headers:
  Content-Type: application/json
  Accept: application/json, text/event-stream

Body (品牌任务示例):
{
  "jsonrpc":"2.0","id":1,"method":"tools/call",
  "params":{
    "name":"create_records",
    "arguments":{
      "baseId":"YQBnd5ExVEwOpmXnIggdl7kG8yeZqMmz",
      "tableId":"hERWDMS",
      "records":[{"cells":{
        "task_type":{"name":"brand"},
        "status":{"name":"pending"},
        "in_attachment_values":"{{brand_raw}}"
      }}]
    }
  }
}

# 品类任务把 cells 换成：
#   "task_type":{"name":"category"},
#   "status":{"name":"pending"},
#   "in_product_name":"{{product_name}}",
#   "in_client_category":"{{client_category}}"
复制
4.2 读取结果（轮询 done） 
POST {{DINGTALK_MCP_URL}}
Headers: Content-Type: application/json
Body:
{
  "jsonrpc":"2.0","id":2,"method":"tools/call",
  "params":{"name":"query_records","arguments":{
    "baseId":"YQBnd5ExVEwOpmXnIggdl7kG8yeZqMmz",
    "tableId":"hERWDMS","limit":10
  }}
}
# 解析 data.records[]：
#   cells["5MNxSsU"].name == "done"  → 该行完成
#   cells["WxgsdDw"]              → 结果 JSON 字符串（再 json.loads）
# 建议：提交后循环轮询，直到目标行 status==done
复制
备选（标准但需建应用）：在钉钉开放平台建一个企业内部应用，拿 appKey/appSecret 换 access_token，再调 AI 表格开放 API 写记录。 优点是有官方文档与限额保障；缺点是多一步应用配置。本方案默认用 4.1/4.2 的 MCP-JSON-RPC 直连，零额外配置。

⑥ 故障排查

现象原因 / 处理
WinError 193 不是有效的 Win32 应用程序直接 exec 了裸 mcporter（sh 脚本）。脚本已自动改用 mcporter.cmd，无需手动处理。
INVALID_SELECT_WRITE_FORMAT单选出参写成 {"text":"x"}。改为 {"name":"x"}。
行一直 pending 不处理本机服务未启动 / 端口不对 → 中继保留 pending 重试；先确认 /health 正常。
token is illegal（写表报错）DINGTALK_MCP_URL 被截断或重复拼接了 ?key=。该 URL 只应出现一次 ?key=。
Dify HTTP 节点收不到工具结果确认 Body 是 JSON-RPC 信封（含 method/tools/call 与 params.name/arguments），Accept 含 text/event-stream。
